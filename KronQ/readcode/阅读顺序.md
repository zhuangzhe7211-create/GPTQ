# KronQ 代码阅读顺序

先理解 GPTQ 的输入侧 Hessian，再看本项目如何加入输出侧曲率。

1. [README.md](../code/README.md)：看 `Reproduce from scratch` 和目录说明。
2. [scripts/run_example.sh](../code/scripts/run_example.sh)：看预计算、量化、部署三个阶段。
3. [main.py](../code/main.py)：看 `main()`，找到 `bi_calibration` 对应的 `kronq_fwrd()` 调用。
4. [common/data_utils.py](../code/common/data_utils.py)、[common/model_utils.py](../code/common/model_utils.py)：看输入和模型结构。
5. [common/quant_utils.py](../code/common/quant_utils.py)：看权重量化刻度和包装层。
6. **[calib/precompute_gradients.py](../code/calib/precompute_gradients.py)**：看输出侧梯度统计如何生成并保存为缓存。
7. **[calib/kronq_utils.py](../code/calib/kronq_utils.py)**：看 `kronq_fwrd()`，追踪输入侧统计、输出侧缓存以及量化补偿。
8. **[calib/incoherence.py](../code/calib/incoherence.py)**：看输入和输出两侧的旋转、缩放如何配合。
9. [calib/inter_layer_mp.py](../code/calib/inter_layer_mp.py)：看如何按敏感度给不同子层分配位宽。
10. 最后看 [runtime/packed_io.py](../code/runtime/packed_io.py) → [runtime/biip_linear.py](../code/runtime/biip_linear.py) → [runtime/bench_decode.py](../code/runtime/bench_decode.py)，理解压缩存储和推理速度。

第一轮跳过 CUDA 内核及多卡评估。`eval_pretrained.py` 用来加载已经量化的模型，不是学习量化算法的第一入口。仓库 W3 走浮点承载的 fake-quant 路线，并不表示 3-bit 在原理上无法打包。

## 核心文件具体做什么

| 文件 | 作用 |
|---|---|
| `scripts/run_example.sh` | 展示梯度预计算、KronQ量化、保存和部署评估的完整命令链。 |
| `main.py` | 总入口：解析量化参数，加载模型和数据，选择KronQ校准并保存结果。 |
| `common/data_utils.py` | 准备校准样本和困惑度评估数据。 |
| `common/model_utils.py` | 查找模型线性层并处理不同模型结构。 |
| `common/quant_utils.py` | 定义量化范围、scale/zero和量化层包装。 |
| `calib/precompute_gradients.py` | 预先计算输出侧梯度/曲率信息并写入缓存。 |
| `calib/kronq_utils.py` | KronQ主体：组合输入侧与输出侧统计，执行双侧误差感知量化。 |
| `calib/incoherence.py` | 实现输入、输出两侧的旋转和缩放，改善量化分布。 |
| `calib/inter_layer_mp.py` | 根据模块敏感度在层间分配不同位宽。 |
| `runtime/packed_io.py` | 定义量化权重和元数据的打包、保存与读取。 |
| `runtime/biip_linear.py` | 用KronQ压缩表示替换普通线性层。 |
| `runtime/bench_decode.py` | 测量解码阶段的实际速度和显存。 |

`common/`放公共数据、模型和量化工具；`calib/`是算法主体；`runtime/`负责压缩格式与推理；CUDA目录最后再读。

本文件依据本地源码整理；未运行实验。
