# 第二轮报告：调好补偿系数后，加权还有效吗？

2026-09-26。所有结果来自本机实际运行；本轮已经完成，原始数据保留。

后续：[第三轮方法迭代及累计总结](round3_report.md) 已扩展到三个目标模块、较大校准集和新的预留文章。本文件保留第二轮当时结论。

## 先看结论

**实验流程更可信了，整体量化效果也改善了，但当前加权方案没有超过调好参数的基线。**

第一轮固定 alpha=0.25 时，梯度加权的小幅收益在独立测试上仍能观察到。然而，当普通 ResComp 和加权方法都公平尝试 alpha=0.25、0.5、1.0 后，全部选择了 0.5；此时普通 ResComp 的测试 PPL 更低。

- 普通 ResComp：测试平均 PPL **27.2615 → 27.1241**，约改善 **0.504%**。这是补偿系数调优的收益。
- 原始教师梯度加权：调参后 **27.1465**，没有超过普通 ResComp 的 **27.1241**。
- 量化前缀状态下采集梯度：**27.1415**，也没有超过基线。这个改进假设本轮未得到支持。
- 全输出共享一组 token 权重：**27.1319**，量化内核耗时比四组教师加权减少约 **75.1%**，但没有精度优势。
- 本轮平均 PPL 最低的是 **GPTAQ 参考实现 27.1048**，它在验证集均值上也最低。

所以，现在不能说“梯度加权稳定优于 ResComp”。更准确的结论是：**它在较弱的固定补偿设置下有收益，但收益会随补偿系数改变；优先建立调参充分的基线，再研究权重代理。** 这不否定所有可能的任务加权方法，只限制了当前模型、模块和参数范围下的结论。

## 本轮究竟优化了什么

| 改进 | 为什么做 | 实际结果 |
|---|---|---|
| 同预算 alpha 搜索 | 第一轮只固定 0.25，可能低估普通方法 | 0.5 更好，调参收益大于此前加权收益 |
| 前缀量化后重新求梯度 | 第一轮目标输入漂移很大，浮点梯度可能不适合 | 实现可运行，但没有超过调参基线 |
| 四组改成共享一组 | 减少重复统计和矩阵求解 | 内核约快 4 倍；精度接近但未超过普通 ResComp |
| 每方法多个打乱对照 | 检查是否真正依赖任务对齐 | 原始教师权重在 alpha=0.25 有一定信号，前缀梯度对照不支持预期 |
| 验证选择后冻结，再独立测试 | 避免把选参数据当最终证据 | 所有设置在加载 test 前保存，包含权重 SHA256 |

优化对象是量化方法与实验流程。预训练 Qwen 权重来源、模型结构、目标模块和公共前缀保持一致，没有微调或重新训练语言模型。

## 设置和工作量

- Qwen2.5-0.5B，revision `060db6499f32faf8b98477b0a26969ef7d8b9987`，CUDA/FP32，关闭 TF32，4-bit 权重假量化。
- 目标 `model.layers.12.self_attn.o_proj`，前 12 个完整 block 的 84 个 Linear 使用相同 RTN 前缀。
- 校准 seed 0/1/2，每次训练集 32×256 tokens；三次共享验证集 64×256 窗口，每次计分 16,320 tokens。
- 所有方法族各有三个 alpha 候选：0.25、0.5、1.0。ResComp 的 alpha2 固定 0.25。rho=0.5、damp=0.01、blocksize=128；四组方案按连续输出通道分组。
- 每个校准 seed 运行 26 个量化候选，三个 seed 共 **78 个候选**，另外评估浮点模型和公共前缀。包括 27 个打乱权重对照。
- 独立 test 使用官方 WikiText-2 raw test split。排除与校准/验证相同的文本和 token 窗口，固定随机顺序，每个文本行取第一个 256-token 窗口；共 **128 个窗口，32,640 个计分 tokens**，来自 36 个顶层文章标题分组。
- 5 个选定方法族和 2 个固定参数对照，各在三组校准所得权重上评估，共 **21 个测试候选**。此外测浮点和公共前缀。
- 事前设置见 [第二轮协议](20260926_round2_protocol.md)。本轮没有根据 test 再调参或扩展搜索。

这些 PPL 属于本地固定窗口协议，不能直接与论文中的标准 WikiText 全语料 PPL 对比。这里的 GPTAQ 是本地神经元分解参考，ResComp 是官方模块核心加本地统一量化网格，均不代表官方完整模型结果。

## 独立测试结果：检查泛化

PPL 越低越好。这里的 test 与第一轮的 validation 不同，不能把两轮不同集合的 PPL 直接相减。

| 方法 | alpha | seed 0 | seed 1 | seed 2 | 平均 PPL |
|---|---:|---:|---:|---:|---:|
| 普通 ResComp，旧设置 | 0.25 | 27.271697 | 27.246914 | 27.265891 | 27.261500 |
| 教师加权，旧设置 | 0.25 | 27.253250 | 27.212610 | 27.261077 | 27.242313 |
| **普通 ResComp，调参后** | **0.5** | **27.136824** | **27.110396** | **27.125032** | **27.124084** |
| GPTAQ 参考，调参后 | 0.5 | 27.136152 | 27.104601 | 27.073602 | 27.104785 |

参考锚点：原始浮点模型 test PPL=18.177097；仅公共 RTN 前缀、目标模块仍浮点时 PPL=27.486669。前缀造成的退化仍然是主要问题，单个目标模块改进只能恢复一部分。

## 任务权重真的比乱序权重好多少

下面仅使用验证集、固定 alpha=0.25；每个校准 seed 有 3 次打乱，共 9 个配对比较。它们共享数据，不是 9 个独立实验。

| 权重来源 | 对齐权重优于打乱的次数 | 对齐平均 CE − 打乱平均 CE |
|---|---:|---:|
| 教师梯度，四组 | 8/9 | -0.000665 |
| 前缀状态梯度，四组 | 2/9 | +0.000531 |
| 教师梯度，共享一组 | 6/9 | -0.000087 |

原始教师梯度在这个固定设置下有正向信号；改用前缀状态梯度没有带来预期改善。不能由此断言 alpha=0.5 的任务对齐效果，因为本轮打乱对照只预先设置在 0.25。

## 差异是否只是抽样波动

另作探索性配对 bootstrap：先对每个 test 窗口的三个校准 seed 差值求平均，再按文章标题分组重采样 5,000 次，避免把同文段落和不同 seed 误当独立样本。以下是 CE 差值的百分位区间，负数有利于表中前一个方法。

| 比较 | 平均 CE 差值 | 探索性 95% 区间 |
|---|---:|---:|
| 教师加权0.5 − 普通ResComp0.5 | +0.000828 | [+0.000306, +0.001319] |
| 前缀梯度0.5 − 普通ResComp0.5 | +0.000641 | [+0.000313, +0.000992] |
| 单组加权0.5 − 普通ResComp0.5 | +0.000287 | [-0.000076, +0.000619] |
| 教师加权0.25 − 普通ResComp0.25 | -0.000704 | [-0.001141, -0.000269] |
| 普通ResComp0.5 − 普通ResComp0.25 | -0.005053 | [-0.005940, -0.004078] |

这项分析不是事前显著性检验，条件于当前三个校准样本，没有多重比较校正；文章分组依赖数据标题结构。它帮助描述不确定性，不证明跨模型、跨层或全模型普遍优势。

## 成本

| alpha=0.5 的方法 | 平均模块量化耗时 |
|---|---:|
| 普通 ResComp | 0.437 秒 |
| GPTAQ 参考 | 0.312 秒 |
| 教师梯度，四组 | 1.809 秒 |
| 前缀状态梯度，四组 | 1.722 秒 |
| 教师梯度，共享一组 | 0.451 秒 |

共享一组比四组教师加权少约 75.1% 内核时间，接近普通 ResComp；但加权还需要梯度采集。每个 seed 教师梯度采集约 1.76–1.90 秒，前缀梯度采集约 1.63–1.73 秒，未包含在表中的内核时间里。

三次完整候选扫描共约 287 秒，独立测试阶段约 89 秒（不含模型加载）。扫描峰值 PyTorch 已分配显存约 2.55 GiB；不是整机 GPU 总占用。计时受运行顺序和本机状态影响，不是正式性能 benchmark。

## 对你的研究意味着什么

已经验证：实现能跑、第一轮结果可复现、固定0.25下的小收益能出现在新测试文本、补偿系数和任务权重有明显相互作用。

尚未验证：充分调参后任务加权能否稳定带来额外收益。当前证据反而提示，不应以默认 alpha=0.25 的 ResComp 作为唯一强基线。

下一轮值得研究的是不同目标层和更合理的公共前缀，或者明确把输入漂移补偿强度与任务权重分开估计。低成本单组方案可以保留为候选，前缀梯度方案暂不作为主线。若继续开发，本次 test 已被查看，不能再作为反复试验后的独立最终测试；需要新的预先冻结评估协议。
