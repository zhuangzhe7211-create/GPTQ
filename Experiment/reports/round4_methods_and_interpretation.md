# 第四轮：方法、核查与解释边界

本文件是第四轮报告的技术附件。最终数字和投入判断以 `round4_report.md` 为准；这里不预先宣告方法胜负。

## 这次实际改变了什么

前三轮主要使用 RTN 前缀：直接把前面块的每行权重按固定网格取整，没有利用输入激活补偿取整误差。第四轮增加校准 GPTQ 前缀：在同样的 W4 网格上，根据校准激活构造输入二阶统计量，量化一列后把误差传播到尚未量化的列。

这里的 GPTQ 前缀是本地实现的块级流程：每个 Transformer 块先在当前输入上收集所有线性模块的 H，再分别量化这些模块，最后把该块量化后的输出传给下一块。块内没有在每量化一个子模块后重新收集后续模块统计量。因此它不是官方完整 true-sequential 流程，也不包含 act-order、输入通道分组、旋转或 clipping 搜索。

q/k/v 共用同一输入，gate/up 共用同一输入，分别复用统计量。三个校准 seed 各自生成一个前缀。各候选在同一 seed 中严格共享同一前缀，前缀的改进不能计为任务加权本身的贡献。

目标从单一注意力输出模块扩展到两种结构：第 12 块的 `self_attn.o_proj`（896×896）与 `mlp.up_proj`（4864×896）。每次只替换一个目标模块；比较 MLP 时注意力目标恢复为原始浮点权重，反之亦然。目标块内其余模块及后续块均保持浮点。这里的“第 12 块”使用从零开始的编号。

## 四类方法在求解什么

固定浮点目标为 `W0 Xf`，当前量化前缀产生的输入为 `Xq`。保持目标权重原始网格不变，误差为 `E = Q Xq - W0 Xf`。

- ResComp：固定版本的官方模块核心，使用未加权统计量。这里并非官方完整模型基准复现。
- GPTAQ：项目里的神经元分解参考，关闭 beta 项；和官方 block 核心的具体计算路径不同。
- weak1：所有输出通道共用一套 token 权重，以通道平均平方梯度为分数，rho=0.1。
- rms1：同样只用一个组，对通道平均平方梯度开平方，再归一化与截断，rho=0.25。

加权统计量始终为 `H = Xq D Xqᵀ / N` 和 `C = (Xf-Xq) D Xqᵀ / N`，两者使用相同的 D。分数先归一化、上限截断为 10、再归一化，最后与全一权重混合。RMS 的开平方在归一化和截断之前完成。

alpha 是补偿强度；rho 是任务分数与均匀权重的混合比例，不能混为一谈。四个方法族各扫描同样的 alpha={0.25,0.5,1,1.5}，分别用三个 seed 的平均验证 CE 选参。另外保留目标模块 RTN 和无输入漂移补偿的 GPTQ 参考。GPTQ 参考不是简单把官方 ResComp 的 alpha 设为零，因为后者的 beta 仍固定为 0.25。

所有梯度来自原始浮点教师和校准集，未使用新预留集拟合。单组权重可以改变不同 token 的重要性，但没有保留独立输出通道方向，因此不能把它描述成完整方向敏感的任务度量。

## 数据与统计怎么隔离

模型固定为 Qwen/Qwen2.5-0.5B，提交 `060db6499f32faf8b98477b0a26969ef7d8b9987`。WikiText2 数据固定提交 `b08601e04326c79dfdd32d625aee71d232d685c3`。每个校准 seed 使用 64 个长度为 256 的窗口；开发验证也是 64×256，三个 seed 共用同一验证集。

新预留集是 train split 中尚未使用的 128 篇文章，每篇一个 256 token 窗口。排除 136 篇实际校准文章和第三轮的 128 篇预留文章，按文章而不只是按窗口隔离。还检查了与第二轮官方 test 已用窗口的文本哈希、token 哈希均无交集。它不叫官方 test，也不是新领域或外部数据集。

先冻结四种上下文、四个方法族的全部选择及目标权重哈希，再读取新预留窗口并评估。128 个窗口每个计分 255 个下一词预测，共 32,640 个 token。PPL=exp(CE)，表中平均 PPL 是三个 seed 各自 PPL 的算术平均；相对改善由配对平均 CE 取指数得到，两者定义略有不同。

不把三个 seed 当作三个独立语言语料库。区间先在同一篇文章上对 seed 的 CE 差取平均，再按文章进行 10,000 次配对 bootstrap。区间只反映这一预留文章集合、这些校准 seed 下的抽样波动，未覆盖模型、数据集和方法筛选的不确定性，也未做多重比较校正。

## 程序问题与修复记录

新增 GPTQ block 核心与独立逐列参考在三个 blocksize 上逐元素一致；加上已有加权恒等式、退化端点等检查，共 16 项通过。

第一次 MLP 扫描在生成梯度分位数诊断时失败：4864×16384 的梯度矩阵超过 PyTorch `quantile` 的输入元素数限制。此时尚未生成或比较目标候选。修复仅对日志里的分位数使用确定性等间隔抽样，最多约 100 万个元素；模型拟合、H/C、任务分数与评估仍使用全部数据。

旧的三个 RTN/attention 扫描保留原诊断代码，后续扫描用新诊断代码。源码快照保存两个版本，评估脚本明确允许这两个版本，并记录变更仅涉及诊断。失败运行保留在 `results/round4_failed_rtn_mlp_s0_diagnostics/`，不计为完成实验。历史指标键 `common_rtn_prefix` 被复用；GPTQ 扫描的前缀身份以 config.json 的 prefix 和 prefix_checkpoint 为准，该指标键不表示它仍是 RTN。

首次最终评估在前缀复现检查处停止，当时只评估了浮点参照，没有评估任何候选的预留成绩。原因是评估脚本在 CPU 上重新执行 RTN，而扫描在 CUDA 上执行。诊断发现 84 个模块共 69,018,948 个假量化浮点存储值不逐位相同，其中量化整数格点实际改变 166,247 个；两者不可混同，大部分存储差异只是尺度末位舍入。CPU 路径前缀验证 CE=3.3945143930613995，原 CUDA 路径为 3.3959439769387245。

修复使评估重建也在 CUDA 上执行，原验证 CE 精确复现；未放宽 1e-6 检查阈值。失败记录保存在 `results/round4_failed_holdout_prefix_device/`。重跑前逐项验证选择、开发成绩、配置哈希、候选权重哈希、前缀哈希和预留数据哈希均与最初冻结文件一致。源码和诊断分别保存在 `round4_source/` 与 `round4_prefix_device_diagnosis.json`，没有利用候选预留成绩重新选参。

## 应该怎样解释结果

本项目想法的核心——下游任务对不同误差的容忍度不同——具有合理动机。但当前验证的是一个具体近似：“通道分组后的梯度平方/RMS token 权重 + ResComp 模块核心”，不能把这个近似的成败扩大为所有任务感知量化的成败。

真实任务损失的局部变化包含一阶项 `gᵀe` 和二阶项 `eᵀHe/2`。非负平方误差代理忽略误差符号和交叉项。以 `g=(1,1)`、`e=(1,-1)` 为例，`gᵀe=0`，而逐坐标平方代理为 2；这解释了为什么降低加权 MSE 未必降低 CE。它只是解释可能机制的数学例子，并不是本实验已测得的唯一失败原因。

若进一步研究，先检验代理能否排序真实候选误差，再决定是否投入更复杂的求解器：在独立开发数据上比较普通 MSE、现有加权代理、保留符号的一阶项或含少量方向的曲率近似，检查它们与实际 CE/KL 差的关系。新增代理有预测能力之后，再实现相应补偿更新。不能先把更复杂的公式当作必然进步。

本地 Qwen2MLP 源码确认其运算为 `down(silu(gate(x)) * up(x))`。单独补偿 up 分支时，另一路 gate 仍接收漂移后的输入。若把激活后 gate 记为 a，up 输出记为 u，则乘积偏差为 `a_q*(u_q-u_f)+(a_q-a_f)*u_f`。只让 `u_q` 靠近 `u_f`，并不自动消除第二项，也可能打破两项的误差抵消。因此后续一个更具体的假设是：在 gate/up 合流之后或整个 MLP 输出上检验重建目标，比较联合分支目标与当前单分支目标。此处只是结构上可推导的待检验解释，本轮没有证明它就是全部性能差异的原因。

若改用教师分布 KL，要注意学生等于教师时 KL 的一阶梯度为零；直接把这个零梯度平方不能估计非零曲率。应单独定义二阶或采样方向估计，再验证实现与成本。

单模块上的 0.1% PPL 筛选门槛是本轮预先写下的投入判断标准，不是公认显著性标准，也不能数学上排除许多小改进在整模型中累积的可能。但在缺乏稳定跨模块收益时，直接扩大为昂贵全模型加权实验并不是当前证据最支持的下一步。

所有实验是 F32 上的 W4 假量化，不是 W4A16 实测、packed int4 部署或推理加速结果。本轮没有重新检索相关文献，不能据此评定创新性。若最终进入论文路线，必须另行完成正式基线复现、全模型实验和查新。
