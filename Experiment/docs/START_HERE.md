# 用白话读懂这次实验

最新结果见 [完整实验报告](../reports/final_report.md)：原梯度加权没有稳定超过强基线；第五轮完整块重建有局部收益，第六轮发现它在另一层和另一语料上可能失效，第七轮检验收缩权重改动、修正输出均值和双域选参。下面先解释原始想法，报告中再说明每次转向及确认结果。

## 一句话说明你的想法

把模型权重量化到 4 bit 后会产生误差。你的想法是：补偿这些误差时，给“对最终预测更重要”的位置更大的权重，而不是把每个位置都同等对待。

这里不重新训练一个语言模型。我们加载已有 Qwen 模型，替换某个线性层的权重，比较它对下一词预测的影响。

## 从 GPTQ 到你的方案

| 方法 | 直观上做什么 |
|---|---|
| RTN | 每个权重直接四舍五入到量化网格，不补偿 |
| GPTQ | 量化一个输入列后，调整剩余列，减少该模块的输出变化 |
| GPTAQ | 还考虑前面层量化造成的输入变化 |
| ResComp | 补偿时保留原始浮点权重，处理补偿过程中产生的额外偏差 |
| 你的加权版本 | 在 ResComp 中，让不同 token 对重建误差的贡献不同 |

这是帮助理解的概括，严格公式见推导文档。当前脚本中的 GPTQ/GPTAQ 是参考实现，不能直接当成各论文完整复现。

## 四个最重要的张量

- `W0`：量化前的原始权重。原始重建目标始终由它决定。
- `xf`：原始浮点模型给该模块的输入。
- `xq`：前面层被量化后，该模块实际收到的输入。
- `grad`：最终预测损失对该模块输出的梯度，用平方作为重要性代理。

普通目标大致是让 `Q @ xq` 靠近 `W0 @ xf`。加权版本给这些输出误差逐 token 乘上不同的正权重。

`make_weights` 把输出通道分组，对组内梯度平方求平均，再做归一化、裁剪和混合。`rho=0` 表示全部用普通权重；`rho=0.5` 表示普通权重和敏感度各混合一半。组数越多，需要处理的统计量通常也越多。

`statistics` 同时计算加权输入相关矩阵 H 和输入漂移的交叉统计 C。只改 H 不改 C，会让补偿依据不一致。

梯度平方只是重要性的近似。它不是精确曲率，也不保证加权重建误差下降后，真实预测损失一定下降。

## 为什么第一轮只动一个模块

我们先把前 12 个 block 的权重统一做 RTN，制造相同的输入漂移，再用不同方法量化第 13 个 block 的注意力输出投影 `layers.12.self_attn.o_proj`。索引从 0 开始，所以 12 对应第 13 个 block。

所有候选使用同一个前缀，便于观察目标模块方法的差别。代价是它不能回答“完整模型量化是否有效”；完整前缀已经损失的能力，一个模块只能补回一部分。

## 怎么判断有没有用

| 名词 | 怎么理解 |
|---|---|
| 校准集 | 用来采集输入、梯度和量化统计量 |
| 验证集 | 比较方案，选择 alpha 等设置；不能再当最终独立证据 |
| 测试集 | 设置冻结后才评估，用来检查是否泛化 |
| CE | 下一词预测的交叉熵，越低越好，是本实验的主指标 |
| PPL | `exp(CE)`，同样越低越好；依赖文本切分协议 |
| MSE | 模块输出的平方误差；它低不等于最终任务一定好 |
| seed | 控制校准文档或打乱权重的随机顺序 |
| alpha | 输入漂移补偿的强度；不是任务权重 rho |

第一轮三次都略有改善，但幅度很小，打乱权重也改善了部分结果。必须继续追问：是任务重要性真的有用，还是只要改变统计量或调好 alpha 就能获得类似改善？

## 第二轮优化的理由

1. **公平调 alpha**：普通 ResComp 和加权版本都试相同的三个值，防止只给新方法调参。
2. **换梯度采集位置**：前缀已量化时重新求梯度，判断是否更贴近实际误差环境；原始重建目标仍保持不变。
3. **一个共享组**：尝试只用一套 token 权重，检验是否能减少成本且保留效果。
4. **冻结后独立测试**：不靠反复观察同一验证集来宣布有效。

## 第四轮增加了什么

第四轮结果见 [第四轮报告](../reports/round4_report.md)。它把前面的 RTN 量化前缀换成利用校准输入的 GPTQ 前缀，并增加 MLP 的 up 分支作为另一类目标，检查加权是否只在某个注意力模块上偶尔有效。

阅读时分清两件事：前缀改好带来的收益，属于基线升级；在同一前缀内，加权目标比普通目标好多少，才是你的加权想法的证据。每次仍只比较一个目标模块，不是整个模型都使用了任务加权。
