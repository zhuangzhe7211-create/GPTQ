# 从原始想法到七轮实验：看得懂的技术说明

更新日期：2026-09-28。配套数字、逐seed结果、置信区间和历史记录见[完整实验报告](../reports/final_report.md)。本文解释“做了什么、为什么做、代码怎么对应”，不用先读懂论文才能阅读。

## 1. 我们到底想解决什么

语言模型内部有很多权重，可以把它们理解成控制信息传递强弱的旋钮。原模型的旋钮刻度很细，量化把刻度变粗，模型可能因此变得不准确。

例如，假设某一行权重的刻度间距为0.1，原来0.23可能被存成整数码2，计算时对应0.2。把数值放回网格很容易；困难在于几百万次取整共同改变了模型输出。

你的想法是：修复量化误差时，**不同位置对最终预测的重要程度不同，重要的位置应该得到更多关注。** 这是一个可以写成代码、可以验证的问题。实验要回答的不只是“能不能运行”，还包括“它是否比同样预算下的普通方法更好”。

需要区分两个经常混淆的“权重”：

| 名字 | 实际是什么 |
|---|---|
| 模型权重W | 线性层里需要量化的参数，例如up_proj矩阵 |
| 误差权重s | 给不同token误差乘的系数，表示修复时更关注谁 |

我们的原始改动主要是设计第二种权重，再让它影响第一种权重的量化结果。

## 2. 这次实验用了什么，没做到哪一步

模型是固定版本的Qwen2.5-0.5B。后几轮使用GPTQ量化的前12个解码块，分别研究第12或18层的`mlp.up_proj`。这里层编号从0开始，代码中的第12层是人按顺序数的第13层。

第18层实验中，前12块仍使用同一GPTQ前缀，中间的12–17块保持浮点。不是“前18层全部量化”，也不是同时修复第12和18层。这样能在比较方法时控制其它因素，但也限制了结果的适用范围。

目标权重矩阵大小为4864×896，共4,358,144个参数。后几轮每次只改变这个矩阵，均值补偿方案另加896个参数。

量化使用每输出行一个固定scale，把整数码限制在[-8,7]。本实验把量化后的值重新存为F32并计算，这叫**假量化**：数值确实落在4-bit网格上，存储格式和计算内核却不是实际int4。因此这些实验能研究精度，不能证明文件已缩小到4-bit大小，也不能证明推理加速。

## 3. 一次实验怎样走完

可以把流程看成以下六步：

1. **准备原模型。** 它是教师，告诉我们没有量化时中间输出是什么样。
2. **准备校准文本。** 每个seed用64段、每段256个token。用这些文本收集层输入、教师输出，必要时还收集梯度。
3. **建立相同量化起点。** 同一比较里的前缀、初始化权重、量化网格保持一致。
4. **计算候选修复。** 调统计量、重建块输出，或对已学修复做收缩和均值补偿。
5. **用开发集选配置。** 开发集允许看，因而不能再用它证明最终泛化能力。
6. **冻结后用新文本确认。** 先保存配置、权重和源码的哈希，再评估新文本；不能看到确认结果后回头改本轮赢家。

校准、开发、确认三种数据分别像“练习题”“选解题方法的模拟题”“选完方法才做的确认题”。重复看过的确认题，下一轮可以变成开发题，但必须换新的确认题。第六轮PTB test在第七轮就是这样转为开发数据的。

这里的seed主要改变校准样本及相应前缀，不是训练三个全新的语言模型。三个seed都改善，比只一个seed特别好更可靠，但仍不等于所有模型和文本都有效。

## 4. 最初怎样把你的想法变成代码

模型预测下一个token时会产生损失L。对某个中间输出z求梯度，得到“这个输出微小改变时，损失大约会怎么变”。梯度较大意味着局部更敏感，但不意味着该token在语言学上天然更重要，也不保证有限幅度的量化变化服从这个局部近似。

`quant_core.py`中的`make_weights`做了这些事：

1. 对一组输出通道的梯度平方求平均，得到每个token的敏感度分数。
2. 归一化并裁剪特别大的分数，避免少数token完全主导。
3. 与全一权重混合：`s=(1-rho)+rho×归一化分数`。

`rho=0`表示完全不加权；rho越大，越偏向梯度认为重要的位置。后面还试过平方分数开方，即RMS形式，减少大梯度对排序和尺度的影响。

然后`statistics`把**同一组s**放入两个统计量：

```text
H = (Xq × s) @ Xq转置 / token数
C = ((Xf − Xq) × s) @ Xq转置 / token数
```

`Xf`是浮点模型给目标层的输入，`Xq`是量化前缀给它的输入。H描述当前输入如何变化，C描述量化前缀造成的输入漂移。这里的“×s”表示每个token所在的列乘相应分数，`@`表示矩阵乘法。

为什么两个都乘？因为我们要改变的是同一个重建问题的关注重点；只改H、不改C，会使补偿项和误差项使用不一致的样本权重。

官方ResComp核心根据这些统计量逐列量化和补偿。我们保留固定版本源码及哈希，用适配器传入新的H和C；没有把全部上游训练流程复制一遍。另有可读的参考实现用于数学与端点检查。

还加入了**打乱权重**对照：保留分数的大小分布，打乱它与token的对应关系。如果打乱后同样变好，收益就可能来自一般性的统计扰动，而不是正确识别了任务重要性。

## 5. 为什么后来转向“完整块重建”

只让一个线性层的输出接近原模型，有时并不能让最终预测变好，因为它后面还会经过门控、投影，并与残差相加。

把后几轮目标块简写成：

```text
块输出 = 残差旁路R + MLP输出M
MLP输出 = down_proj(激活后的gate分支 × up分支)
```

前缀量化不仅影响MLP输入，也可能让残差旁路R发生偏移。如果只追求`Mq≈Mf`，最终`Rq+Mq`仍可能偏离教师`Bf`。

第五轮把优化目标改成：

```text
让 Rq + Mq 尽量接近 Bf
等价于让 Mq 尽量接近 Bf − Rq
```

这就是代码里`teacher=bf-rq`的原因。训练时仍只改up_proj；“完整块目标”表示观察整个块的输出误差，不表示整个块的所有权重都参与训练。

这种目标在第五轮新的WikiText文章上有明显局部收益。然而第六轮换目标层、换PTB语料后收益不统一。因此我们不能把“目标更合理”直接写成“所有层、所有文本都变好”。

### 网格是离散的，怎么优化

直接对round求导无法正常训练。代码保留一个连续的影子码值，前向计算时取整到固定网格，反向计算时用近似梯度更新影子码值。这叫直通估计，见`run_round5.py: fake_weight`。

用Adam优化影子码值，不代表最后保存的是任意浮点权重：正式4-bit候选保存前会再次检查网格。第六轮另设不取整的continuous对照，它只是帮助理解量化约束的作用，不能当成4-bit方法的成绩。

## 6. 第六轮进一步检验了什么

| 改动 | 想回答的问题 | 实际学到的事 |
|---|---|---|
| 192步增加到576步 | 训练更久能否继续进步 | Wiki开发更好，PTB未必更好；存在过度适应的证据 |
| 对完整块误差做弱token加权 | 原想法换到更合理目标上能否奏效 | 没有在两层共同稳定超过强对照 |
| 增加梯度方向误差惩罚 | 不只看哪个token重要，也看哪个输出方向重要 | 更复杂仍没有自动带来外部收益 |
| 限制方向罚项强度 | 是否之前某方向惩罚太强 | 修正后仍未通过统一额外收益门槛 |
| 增加896维均值偏置 | 很小的系统偏移是否解释部分误差 | PTB两层均有正收益，值得作为便宜强基线 |
| 不取整的连续权重 | 是否主要受离散网格约束 | 提供参考，但不能计为量化方法胜利 |

方向罚项形如`普通MSE + λ×mean((u转置e)^2)`。e是完整块误差，u是归一化梯度方向。它是额外的局部敏感度近似，没有计算全模型的真实任务Hessian。

第六轮初始λ=1，在896维输出的这个特定误差目标中，梯度方向相对其它方向的曲率比例达到897。随后在新确认之前改为λ=9/896，使这个比例变为10。这个数是**误差空间目标的方向曲率比例**，不是整个模型参数Hessian的条件数。

## 7. 第七轮做的优化为什么更保守

第六轮提示：不能默认“改得越多、训练越久越好”。因此第七轮复用已经得到的192步修复，检查三个强度，而没有继续加长训练。

设初始GPTQ整数码为q0，完整块修复后的整数码为q1：

```text
新码 = round((1−tau)×q0 + tau×q1)
实际权重 = scale × 新码
tau只试0、0.5、1
```

比如一个码从2修到4，tau=0.5会得到3。若从2修到3，中点2.5按PyTorch的半整数舍入规则可能回到2；所以“半幅”不等于恰好一半的参数改变。

再对每个强度，计算一个块输出偏置：

```text
b = 校准文本上 (教师块输出 − 当前块输出) 的平均值
修正后输出 = 当前块输出 + b
```

它像校正一个仪表的固定偏移：如果仪表总偏高，减去平均偏差。但换环境后偏差可能改变，因此校准平均误差被消掉，并不保证新文本预测一定更准。

b只有896个F32数，原始参数约3.5 KiB。它是额外模型参数，不是免费操作；本实验没测它的部署时延。第七轮是在固定权重上事后拟合b，没有重新联合训练“去均值误差目标”。

每个层和seed有6个条件：三个强度，各自有偏置/无偏置。2层×3seed×6=36条开发条件，其中18条直接复用第六轮，18条是新的后处理计算。不能把全部36条说成新训练。

### 怎么避免只讨好WikiText

对每个候选，分别计算它相对初始GPTQ在Wiki开发集、已见PTB上的平均CE差，取两者较差的那个，再选这个值最低的候选。初始GPTQ本身也可以被选中，允许“不修复”。

例如，这只是解释用的假设数值：A在Wiki改善0.02、PTB退化0.01；B在Wiki和PTB各改善0.005。只看Wiki会选A，看较差域会选B。该规则保障的是已观察开发均值，不能保障所有未来文本。

还冻结了只看Wiki的选择器作对照，避免把所有进步都归因于双域选参。最终两层选择不同：第12层保留完整修复加偏置，第18层选择半幅修复加偏置。它们都在新确认指标计算前固定。

## 8. 怎样看结果才不会被数字误导

**PPL越低越好。** 它是下一token预测平均交叉熵CE取指数，不能解释成错误率百分比。PPL降低1%，不等于准确率提升1个百分点。

**MSE越低，说明某个中间输出更接近教师。** 但模型最终预测经过很多后续计算，MSE与PPL可以反向变化。我们因此同时观察局部误差与完整模型的文本预测指标。

**只能同条件横向比较。** 同样文本、同样前缀、同样目标层，比较初始GPTQ与修复方法。不能把上一轮Wiki PPL与本轮PTB PPL直接相减。

**先看比谁好，再看好多少。** 超过初始GPTQ是第一步；复杂方案还应超过普通完整块、简单偏置等强基线。否则额外梯度计算或权重优化未必值得。

**区间和seed用于看不确定性。** 第七轮每个新语料有32个连续1024-token块，各拆成4个256窗口，配对重采样这些块计算95%区间。它不是32篇独立文章，区间也没作多重比较校正。区间跨0表示方向还不够确定，不能只看均值宣布胜利。

PTB使用此前未评估的官方validation文件，作为本项目的新确认数据；不能冒充标准PTB test基准。Shakespeare是新文本来源，但不能保证预训练模型未见过。精确窗口哈希无交集，只排除了这种精确重复，不排除语义相近或预训练泄漏。

## 9. 七轮分别做了什么

| 轮次 | 核心任务 | 对研究方向的影响 |
|---|---|---|
| 1 | 实现梯度加权H/C，跑真模型与对照 | 能运行，早期收益很小 |
| 2 | 公平调补偿强度、换梯度采集位置、单组共享统计 | 原加权没有稳定超过更强基线 |
| 3 | 三个目标位置、平方/RMS形式、弱权重与退化检查 | 跨层不稳定；修复了rho=0数值端点问题 |
| 4 | GPTQ前缀、注意力与MLP目标、跨前缀比较 | 更强前缀本身的改善不能算加权贡献 |
| 5 | 固定网格优化分支、门控合流、MLP及含残差完整块 | 完整块目标出现明显局部收益 |
| 6 | 两层、外部PTB、更多步数、方向/弱权重/偏置对照 | 发现迁移失效，简单均值偏置值得重视 |
| 7 | 修复收缩、均值补偿、双域选参、新文本确认 | 检验能否减少过度修复；最终数字见完整报告 |

技术上“能实现”已经得到验证。科学上“任务敏感度是稳定收益来源”仍未得到充分支持。之后的完整块、偏置和选参改进不能倒过来算作原梯度权重想法已经成功。

## 10. 黑屏之后修改了什么

没有足够日志证明最初黑屏一定由CUDA OOM造成，因此没有伪造故障原因。实际改动是降低负载，并在接近阈值时退出：

| 设置 | 作用 |
|---|---|
| PyTorch分配器预算4 GiB | 限制本进程通过PyTorch分配的显存 |
| 整卡使用达到8192 MiB停止 | 给桌面、驱动和其它应用留空间 |
| 达到78℃停止 | 温度异常时停止后续队列 |
| 可用RAM不足4 GiB停止 | 防止CPU缓存把系统内存耗尽 |
| 大缓存放CPU，训练微批次64×4 | 保留256token有效批次，减少瞬时显存 |
| 单GPU进程顺序运行 | 不并行堆多个模型 |
| 第七轮每序列暂停150ms，≤65℃启动 | 降低持续负载并避免热启动 |

第七轮40ms旧间歇曾采样到79℃并退出，当时整卡显存约3.9GB，没有OOM记录。随后增加间歇，没有提高78℃停止阈值。另一次中断是调整启动条件时主动结束进程，已和正式结果分开存档。

最终确认还遇到一次写`resources.json`的OSError。已保存71条有效指标，只补跑3条缺失项；原指标和冻结选择保持不变。它是日志写入失败，不能据此说模型质量不好或发生显存溢出。补跑改用临时文件加替换和有限重试保存结果。

监控约每2秒采样，不能记录每个瞬间。4 GiB预算也不等于整卡绝不会超过4 GiB。这些设置降低风险，不是对硬件、供电、驱动故障的保证。详细设置见[安全运行说明](../RUN_SAFELY.md)。

## 12. 下一步应该怎样决定，而不是无限试参数

先看这轮冻结方案在新文本上的实际结果。以下为3个seed的平均PPL，越低越好：

| 新确认文本 | 目标层 | 初始GPTQ | 只加均值偏置 | 冻结的组合修复 |
|---|---:|---:|---:|---:|
| PTB validation | 12 | 49.5566 | 49.1754 | 48.7522 |
| PTB validation | 18 | 49.5715 | 49.4075 | 49.4116 |
| Shakespeare | 12 | 67.5049 | 67.0795 | 66.9359 |
| Shakespeare | 18 | 67.4640 | 67.3208 | 67.3930 |

组合修复对初始GPTQ在四条件都是3/3seed改善；但第18层Shakespeare的区间仍跨0，幅度很小。更重要的是，第18层简单偏置的平均结果更好。你的研究已经找到可复现的局部改进，但“复杂修复一定比简单修正好”仍不成立。

第18层只按Wiki选参会选完整修复加偏置，在Shakespeare上反而比初始GPTQ差；双域规则选半幅后改善。这是此次选择规则有效的具体证据。第12层两个选择器选到同一个方案，不能把相同结果重复解释成两种独立成功。

先问最便宜的方案是否已经解释主要收益。若均值偏置足够好，就保留它作强基线；若保守权重修复还能稳定增加收益，再值得支付更多优化成本。
