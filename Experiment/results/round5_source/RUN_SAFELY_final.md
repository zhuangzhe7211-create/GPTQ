# 当前实验的资源保护

2026-09-27，在用户报告黑屏后增加。仅第五轮新入口已接入这些保护；历史脚本不能自动获得保护。

当前入口为 `run_round5.ps1`。它顺序运行初始扫描、完整块追加扫描和冻结后的评估，不并行运行GPU任务。资源实现见 [gpu_safety.py](gpu_safety.py)。

| 项目 | 当前值 |
|---|---:|
| PyTorch显存分配预算 | 4 GiB |
| 启动要求 | 至少5 GiB空闲显存 |
| 整卡显存停止阈值 | 已用达到8192 MiB |
| GPU温度停止阈值 | 达到78℃ |
| 系统内存停止阈值 | 可用RAM不足4 GiB |
| 训练微批次 | 64 token，累积4次 |
| 计算间歇 | 每个评估序列/优化步40ms |

大激活、梯度和教师缓存放在CPU；局部优化时完整模型移到CPU，检查点评估时再移回GPU。监测约每2秒更新；NVML监测峰值是采样值，不是连续硬件峰值。预算仅覆盖PyTorch分配器，不能控制所有驱动或其他应用占用，因此另留整卡余量。

触发阈值、监测失败或计算异常时，进程退出，队列停止。不要为了继续运行直接提高预算或关闭检查；先查看当前运行目录的 `resources.json` 与对应 `.log`。未完成目录会被保留并拒绝覆盖，需先确认原因再用新目录继续。

首次资源短检查见 [记录](results/round5_resource_preflight/resources.json)。它不是质量实验。后续每次正式运行和最终评估也分别保存资源记录。

初次黑屏没有留下足以确定原因的OOM/驱动日志。这些改动降低资源耗尽风险，不保证排除所有硬件、供电或驱动故障。没有调整系统显卡驱动、功耗上限或全局桌面设置。
