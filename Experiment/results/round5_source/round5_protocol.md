# 第五轮预先固定协议（2026-09-27）

目标：检验上一轮 MLP 单分支重建目标与任务指标不一致的问题，不再只扩扫梯度权重。所有配置在新预留模型成绩计算前固定。

## 设置

- Qwen2.5-0.5B、模型和 WikiText2 版本、F32/W4 固定逐行网格、校准 seeds=0/1/2、每 seed 64×256、开发验证64×256均沿用第四轮。
- 两种公共前缀：原 CUDA RTN 前12块、第四轮保存的校准 GPTQ 前12块。只修改第12块 mlp.up_proj，其余目标块及下游权重保持浮点。
- 初始目标权重是第四轮对应 seed/前缀的 GPTQ reference 检查点；所有优化目标共用此初始化和原始浮点权重定义的固定网格。

## 新方法与公平对照

原始浮点教师输入 xf，量化前缀输入 xq；u_f=W_up xf，a_f=silu(W_gate xf)，a_q=silu(W_gate xq)。固定 W_gate、W_down，只改变量化 up 权重 Q。

1. branch：最小化 Q xq 与 u_f 的 MSE，作为同优化器对照。
2. product：最小化 a_q*(Q xq) 与 a_f*u_f 的 MSE。
3. mlp：最小化 W_down[a_q*(Q xq)] 与 W_down[a_f*u_f] 的 MSE。

每种损失除以对应教师目标的均方值；使用代码值空间的 Adam 与 straight-through round，学习率0.01/0.03，batch=256个校准token，保存第32/96/192步。每次更新后裁剪到[-8,7]。三种目标使用相同 minibatch 序列和训练步数。只保留固定网格假量化权重，不能把浮点潜变量当作最终结果。此方法是固定网格量化重建实验，不作算法新颖性声明。

补齐较小 alpha 的对照：ResComp、GPTAQ参考、weak1 各扫描 alpha=0/0.0625/0.125/0.25/0.5；另外评估原目标RTN/GPTQ。每个前缀×seed共35个候选：18个优化检查点+15个补偿对照+2个固定参考；总210个候选。优化方案与原闭式核心耗时不同，分别报告，不称为等计算预算。

## 选参与新评估

- 每个前缀、每个方法族各按三个seed平均开发验证CE选一个共同配置。选择全部冻结，并记录权重/配置/源码哈希，再计算新预留集的候选成绩。
- 从此前未用过的train文章保留最多128篇，一篇一个256token窗口，排除全部实际校准文章与第三、第四轮的全部预留文章，也检查历史test、验证的文本和token哈希。若剩余不足128篇，使用所有合格文章并记录数量；不足64篇则先重新设计数据来源，不声称精度足够。
- 最终评估每个前缀的 branch/product/mlp、ResComp/GPTAQ/weak1 六个选参族和RTN/GPTQ两个固定参考，共48个候选。额外由开发验证从所有非product/mlp候选中选出一个“最强已有对照”，它可以是branch；冻结后原样评估，最多额外6个候选。
- 配对文章bootstrap 10,000次，先在文章内平均seed。探索性区间不做多重比较校正。当前预留集一旦评估，不据其成绩改变配置。
- 支持继续投入的筛选：product或mlp在两种前缀中均超过各自开发集选出的最强已有对照，各至少赢2/3seed、平均相对PPL改善≥0.1%，且区间上界<0；同时应优于同优化器branch对照。达不到就明确区分局部现象与可靠增益，不无休止追加超参数。

## 资源安全修订（首次扫描中断后、新候选优化与预留评估之前）

用户报告黑屏；原运行没有留下可确认原因的OOM/驱动日志，不断言一定是显存耗尽。中断的14个补偿/参考候选保存在 round5_interrupted_rtn_s0，未完成任何新目标优化或选参，不用于最终统计。

改为PyTorch分配器4 GiB预算、整卡显存8 GiB停止阈值、78℃停止阈值、系统可用RAM低于4 GiB停止。每个序列评估及每个优化步后间歇40ms。所有大缓存及教师目标在CPU保存和计算，weak1分数在CPU计算；H/C和量化核心仍在CUDA。训练使用64-token微批次、4次梯度累积，保持256有效batch；索引改为CPU生成且对所有目标/学习率共用。教师CPU/GPU浮点乘法可能有末位差异，不宣称与中断版本逐位一致。三个目标均使用相同CPU缓存，评估及原权重前缀一致性检查保持不变。

训练阶段将完整模型移到CPU，只保留所需小张量和可优化权重在GPU；检查点评估时再移回GPU。大矩阵重建指标按512-token片段累计。所有设置及间歇同时作用于对照，不据新预留成绩改变实验。资源短检不是质量证据；安全预算降低风险，不保证排除所有驱动或硬件黑屏原因。
