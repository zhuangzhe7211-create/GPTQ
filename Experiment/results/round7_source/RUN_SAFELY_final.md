# 当前实验的资源保护

2026-09-28更新。用户报告黑屏后，第五、六、七轮入口接入保护；第一至第四轮历史脚本不会自动获得这些保护。

当前研究入口为 `run_round7.ps1`；第五、六轮分别为 `run_round5.ps1`、`run_round6.ps1`。均顺序执行，一个GPU任务完成后才开始下一个。共享硬预算见 [gpu_safety.py](gpu_safety.py)，第七轮额外降载设置见 [round7_safety.py](round7_safety.py)。

| 项目 | 当前值 |
|---|---:|
| PyTorch显存分配预算 | 4 GiB |
| 启动要求 | 至少5 GiB空闲显存 |
| 整卡显存停止阈值 | 已用达到8192 MiB |
| GPU温度停止阈值 | 达到78℃ |
| 系统内存停止阈值 | 可用RAM不足4 GiB |
| 第五、六轮训练微批次 | 64 token，累积4次 |
| 第五、六轮计算间歇 | 每个评估序列/优化步40ms |
| 第七轮计算间歇 | 每个评估/捕获序列150ms；不新增Adam训练 |
| 第七轮启动温度 | ≤65℃才开始模型工作；超出时每5秒复查，仍服从78℃硬停止 |

大激活、梯度和教师缓存放在CPU；局部优化时完整模型移到CPU，检查点评估时再移回GPU。监测约每2秒更新；NVML监测峰值是采样值，不是连续硬件峰值。预算仅覆盖PyTorch分配器，不能控制所有驱动或其他应用占用，因此另留整卡余量。

触发阈值、监测失败或计算异常时，进程退出，队列停止。不要为了继续运行直接提高预算或关闭检查；先查看当前运行目录的 `resources.json` 与对应 `.log`。未完成目录会被保留并拒绝覆盖，需先确认原因再用新目录继续。

首次资源短检查见 [记录](results/round5_resource_preflight/resources.json)。它不是质量实验。后续每次正式运行和最终评估也分别保存资源记录。

第七轮原40ms配置曾监测到79℃，保护主动停止，当时整卡显存3940 MiB，没有OOM记录。已保存[停止日志](results/round7_stopped_temperature_l12_s0.log)，正式运行将间歇增加到150ms，没有提高硬停止温度或显存预算。启动条件曾试60℃，最终采用65℃；相关中断与调整过程写入[协议](reports/round7_protocol.md)。

初次黑屏没有留下足以确定原因的OOM/驱动日志。这些改动降低资源耗尽风险，不保证排除所有硬件、供电或驱动故障。没有调整系统显卡驱动、功耗上限或全局桌面设置。
