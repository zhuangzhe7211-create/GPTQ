# REAL-Q 阅读顺序与代码状态

当前 `code/` 只有状态说明，没有 REAL-Q 官方实现，因此先读论文并建立与 GPTQ、GuidedQuant、GPTAQ 的对应关系。

1. [资料来源.md](../资料来源.md)：核对论文 v2 和官方代码状态。
2. 复习 [GPTQ 阅读顺序](../../GPTQ/readcode/阅读顺序.md)：理解静态 Hessian、逐列补偿和 column block。
3. 阅读 [GuidedQuant 阅读顺序](../../GuidedQuant/readcode/阅读顺序.md)：理解 per-token saliency、输出组共享 Hessian；这是 REAL-Q §3.3 的直接前置。
4. 对照 [GPTAQ 阅读顺序](../../GPTAQ/readcode/阅读顺序.md) 与 [ResComp 阅读顺序](../../ResComp/readcode/阅读顺序.md)：理解上游输入漂移与解析残差补偿。REAL-Q处理传播误差的方式不同，不能只因目标相近就视为相同算法。
5. 论文 §3：统一符号，并把 GPTQ 更新式、GuidedQuant 的分组加权 Hessian 写在同一页。
6. **论文 §4.2**：先推 transformer block 输出处的 KL 二阶展开，再区分逐 token Hessian、模型分布下 Fisher 和一次校准得到的梯度外积。
7. **论文 §4.3**：理解每量化完一个 column block 后，只更新尚未量化权重的一步 Adam；已经量化的坐标保持冻结。
8. **论文 §4.4**：看相邻两个 transformer block 目标怎样随全局 block 进度线性混合，以及为什么这需要最多跨两个 block 反向传播。
9. 论文 §5 与附录 C：核对静态求解器误差累积结论和代理梯度的下降条件；注意正文也说明该 SGD 条件不能直接转移到 Adam。
10. [论文附录 A 的伪代码](https://arxiv.org/html/2609.00049v2#A1)：把 Fisher 预计算、解析量化、Block-GD 和 sliding window 串成完整流程。
11. 最后读 §6 与附录 D：核对校准样本数、旋转、学习率、显存和 GPU-hour；这些成本是理解方法可复现性的必要部分。

## 当前文件具体做什么

| 文件/目录 | 作用 |
|---|---|
| `资料来源.md` | 记录论文链接、PDF 和官方代码状态。 |
| `code/README.md` | 说明本地没有官方实现，防止把论文伪代码误认成可运行源码。 |
| `readcode/阅读顺序.md` | 按 GPTQ → GuidedQuant/GPTAQ → REAL-Q 目标与动态更新安排阅读。 |

理解主线：REAL-Q先用任务相关的 Fisher 代理定义 block 输出误差，再在静态解析舍入之间插入动态梯度修正。它的核心不只是“把 GPTQ 的 H 加权”。
