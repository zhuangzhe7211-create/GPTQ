# ResComp 代码阅读顺序

先读 GPTQ，再读 GPTAQ，最后读 ResComp 的残差补偿改动。

1. [README.md](../code/README.md)：看问题定义及其与 GPTAQ 的关系。
2. [fake_quant/gptaq_r_3bit.sh](../code/fake_quant/gptaq_r_3bit.sh)：看当前实际提供的启动参数。
3. [fake_quant/main_r.py](../code/fake_quant/main_r.py)：看整体流程和 `gptaq_utils_r` 的调用位置。
4. [fake_quant/data_utils.py](../code/fake_quant/data_utils.py)、[model_utils.py](../code/fake_quant/model_utils.py)：看模型和校准输入来源。
5. [fake_quant/gptaq_utils.py](../code/fake_quant/gptaq_utils.py)：回顾 GPTAQ 基线。
6. **[fake_quant/gptaq_utils_r.py](../code/fake_quant/gptaq_utils_r.py)**：按 `gptaq_fwrd()` → `GPTAQ.__init__()` → `add_batch()` → `fasterquant()` 阅读；对照上一文件，找原权重、已补偿权重以及残差项如何参与更新。
7. [fake_quant/eval_utils.py](../code/fake_quant/eval_utils.py)：看评估入口。
8. 最后读 [rotation_utils.py](../code/fake_quant/rotation_utils.py) 和 [hadamard_utils.py](../code/fake_quant/hadamard_utils.py)。

当前源码快照有缺失：`main_r.py` 引用了未提供的 `quant_utils.py`、`gptq_utils_r.py`；README 示例中的 `weight_group_*.sh` 也未出现在本地代码中。因此这份路线用于阅读，不能据此声称仓库可直接运行。量化工具的概念可参考 [GPTAQ 的 quant_utils.py](../../GPTAQ/code/fake_quant/quant_utils.py)，但不要把参考实现误认为 ResComp 官方补齐文件。

## 核心文件具体做什么

| 文件 | 作用 |
|---|---|
| `fake_quant/gptaq_r_3bit.sh` | 当前仓库实际提供的3位实验命令，展示模型、位宽和残差补偿参数。 |
| `fake_quant/main_r.py` | 总入口：加载模型与数据，安装量化模块并调用残差补偿版本的GPTAQ流程。 |
| `fake_quant/data_utils.py` | 准备量化校准数据和困惑度评估数据。 |
| `fake_quant/model_utils.py` | 查找、移动和替换模型中的目标层。 |
| `fake_quant/gptaq_utils.py` | GPTAQ基线实现，用于与残差版本逐函数比较。 |
| `fake_quant/gptaq_utils_r.py` | ResComp核心：在GPTAQ校准和误差更新中加入残差相关的补偿。 |
| `fake_quant/eval_utils.py` | 对量化后的模型执行困惑度评估。 |
| `fake_quant/rotation_utils.py` | 对模型权重施加等价旋转以改善量化分布。 |
| `fake_quant/hadamard_utils.py` | 支持旋转所需的Hadamard变换。 |

`fake_quant/`是当前可读的主体。仓库引用但缺失的文件不是可跳过细节，而是会影响直接运行的实际缺口。

本文件依据本地源码整理；未安装依赖或运行实验。
